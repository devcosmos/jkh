# Frontend — интерфейс диспетчера и администратора

React + TypeScript, без UI-фреймворка. Разделы (маршруты в `src/App.tsx`):
Обзор, Риски, Журнал, Заявки, Модели, Объекты и каналы, Аналитика — доступны всем ролям;
Журнал аудита и Пользователи — только администратору. Отдельная страница «Справка»
объясняет каждый раздел на естественном языке.

Большинство разделов пока лежит в `src/pages/`. Риски и Заявки — первые два вынесены в
`src/features/risks/` и `src/features/requests/` (реструктуризация каталогов, шаг 4):
компоненты, которые используются только внутри одного раздела, переезжают вместе со
страницей, а действительно общие остаются в `src/components/`. Остальные разделы
разбираются постепенно, не одним махом — массовое переименование сейчас принесло бы меньше
пользы, чем точечные исправления.

Реальных координат объектов нет (организаторы подтвердили, что их не будет) — вместо карты
иерархическая схема объектов с агрегацией риска (`components/ObjectsTree.tsx`), Leaflet не
используется.

## Локальная разработка

```bash
cd frontend
npm install
npm run dev   # http://localhost:5173, проксирует /api на localhost:8000 (см. vite.config.ts)
```

Backend должен быть поднят отдельно и слушать `localhost:8000` (см. `backend/README.md`).

## Сборка/деплой

Собирается внутри Docker (`Dockerfile`: node → `npm ci` → `vite build` → статика → nginx),
локальный Node не нужен для прод-разворачивания — только для разработки. Разворачивается
как сервис `frontend` в `docker-compose.yml`, за Caddy на проде (`deploy/Caddyfile`):
`/api/*` → backend, всё остальное → frontend. `docker-compose.dev.yml` дополнительно
публикует его на `localhost:5174` для локального просмотра прод-сборки без Caddy.

## Доступ по объектам

Роль сама по себе не ограничивает видимые объекты. Если пользователю не назначено ни
одного объекта (`Пользователи → назначения`), он видит все объекты без ограничений —
сознательное упрощение MVP (см. `backend/README.md`). Ограничение начинает действовать
только после первого назначения.

## Известные ограничения

- Списки (риски, заявки, журнал и т.д.) обновляются только кнопкой «Обновить», без
  поллинга по таймеру. Исключение — уведомления о новых критических рисках
  (`RiskAlerts.tsx`) и счётчик новых рисков в навигации: они опрашивают `/risk-cases`
  каждые 30 секунд сами, в фоне, независимо от того, какая страница открыта — см. раздел
  «Раздел 10 ТЗ» в докстринге `RiskAlerts.tsx`.
- Мобильная адаптация не проверялась целенаправленно.
- E2E (Playwright) есть, но покрывает только основной сценарий и запрет доступа к чужому
  объекту — см. `e2e/README.md`. Поллинг уведомлений и исторический replay worker'а им не
  покрыты.
