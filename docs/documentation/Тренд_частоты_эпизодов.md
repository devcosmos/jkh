# Тренд частоты эпизодов неисправности

Описание сверено с `backend/app/services/degradation_trend.py`.

## 1. Назначение

Показатель сравнивает частоту исторических эпизодов канала в двух последовательных окнах по 90 дней. Он помогает увидеть учащение или сокращение неисправных состояний внутри направления «Отказ датчика». Данных о возрасте оборудования и датах установки нет, поэтому показатель не описывает физический износ и не прогнозирует будущий тренд.

## 2. Источник

Таблица `incident_episodes` заполняется импортом результатов `scripts/build_episodes.py`. Worker её не пополняет. При импорте 21 сентября зафиксировано 182 524 строки за 2024–2026 годы; 123 535 строк отмечены флагом флаппинга и 58 989 остаются после его исключения. Это объём исторической таблицы, а не число целевых эпизодов обучающей выборки из отчёта о разметке.

Расчёт исключает `is_flapping_incident=true` и использует `start_time`. Дополнительной проверки длительности и `left_censored` в сервисе тренда нет. Следовательно, показатель считает начала записей исторической таблицы после фильтра флаппинга; он не воспроизводит все условия обучающей разметки из [label-policy.md](label-policy.md).

## 3. Точка отсчёта

`as_of = max(start_time)` по всей таблице. Сравнение с текущей датой сервера сделало бы исторические окна пустыми. Когда таблица пуста, результат отсутствует. Канал без эпизодов при непустой таблице получает нулевые счётчики и статус `insufficient_data`.

## 4. Расчёт и пороги

- `recent`: начала эпизодов в интервале `(as_of − 90 дней, as_of]`.
- `baseline`: начала эпизодов в интервале `(as_of − 180 дней, as_of − 90 дней]`.
- `total = recent + baseline`.

Условия применяются сверху вниз:

| Условие | Статус | Подпись |
| --- | --- | --- |
| `total < 3` | `insufficient_data` | Недостаточно данных |
| `recent >= baseline × 1.5` и `recent − baseline >= 2` | `worsening` | Учащается |
| `recent <= baseline × 0.67` и `baseline − recent >= 2` | `improving` | Реже |
| Остальные случаи | `stable` | Стабильно |

Окна и пороги — рабочие эвристики. Статус «стабильно» означает отсутствие выраженного изменения по этим условиям, а не исправность оборудования.

## 5. API и реализация

Функция `compute_trend_for_channels` считает показатели группы каналов одним SQL-запросом с условными счётчиками. `get_as_of` отдельно определяет общую точку отсчёта.

- `GET /api/channels/{id}/degradation-trend` — показатель выбранного канала.
- `GET /api/channels?include_trend=true` — показатели для текущей страницы реестра. По умолчанию дополнительный расчёт выключен.
- `GET /api/dashboard/summary` — поле `top_worsening_channels`, до пяти каналов с наибольшим ростом счётчика.

Ответ содержит `channel_id`, `as_of`, длины окон, `recent_count`, `baseline_count` и `status`. Доступ учитывает объектные ограничения пользователя.

## 6. Отображение и проверка

Показатель отображается в реестре каналов, карточке риска и на обзоре. Пояснение связывает его с частотой эпизодов за 90 дней относительно предыдущих 90 дней и указывает, что это историческая статистика.

Проверки в `backend/tests/test_degradation_trend.py` охватывают четыре статуса, минимальный объём, исключение флаппинга, временные границы, согласованность группового расчёта и права API. Датированный результат проверки сохранён в [протоколе](Протокол_проверок.md).
