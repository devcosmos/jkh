# Документация проекта ЖКХ

## Где что находится

- [Исходные данные](../source-data/) — PDF задания, текст ЖКХ.md, дополнительное ТЗ с сайта, ответы организаторов в CSV и исходный шаблон презентации. Исходные материалы собраны отдельно от проектной документации. Таблица «Город 8» получена как CSV-выгрузка из XLSX; отдельного XLSX в прежней папке docs не было.
- [Документы для сдачи проекта](../deliverables/) — сопроводительная документация в Markdown, матрица требований, текст презентации и перечень материалов к отправке.
- Эта папка — описание системы, методики, датированные результаты и технические пояснения.

`data-manifest.json` и `data-profile.json` — сохранённые результаты аудита. JSON-отчёты в `artifacts/` также сохраняют исходные численные результаты. Пути внутри исторических JSON могут отражать прежнее расположение файлов (`docs/documentation/analysis/`); актуальные скрипты используют `artifacts/`.

Крупные файлы обучения `*.parquet`, `*.cbm`, `*.joblib` в `artifacts/` по умолчанию исключены из Git — кроме шести файлов демокомплекта (`replay_feed_*.parquet`, `catboost_*.cbm`, `isolation_forest_*.joblib`), которые читает worker и которые намеренно отслеживаются (см. `.gitignore`). Журналы событий конкурса остаются в `dataset/`.

## Запуск и воспроизведение

Инструкции по сервису и тестам — [backend/README.md](../../backend/README.md), по развёртыванию и резервным копиям — [deploy/README.md](../../deploy/README.md), по воспроизведению потока — [описание worker](../../backend/app/workers/README.md).

Команды аудита выполняются из корня репозитория в подготовленном Python-окружении:

```sh
python3 scripts/data/manifest.py > docs/documentation/data-manifest.json
python3 scripts/data/profile_data.py > docs/documentation/data-profile.json
python3 scripts/build_episodes.py
```

Построение витрин и обучение описаны в отчётах моделей. Эти операции работают с большим объёмом данных и перезаписывают результаты; для чтения документации повторный запуск не требуется.
