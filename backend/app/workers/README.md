# Worker: replay + живой инференс

`replay_worker.py` — единственный фоновый процесс прототипа (раздел 3 ТЗ MVP: «один
отдельный Python worker»). Обслуживает оба независимо оцениваемых трека одновременно (тема
18 CSV с ответами организаторов: «два независимых результата, оцениваются отдельно») — см.
`TRACKS` в начале файла. Что делает на каждом тике:

1. Продвигает общее для обоих треков виртуальное время часовыми тиками (курсор — таблица
   `replay_state`, переживает перезапуск контейнера; оба фида покрывают один и тот же
   период, поэтому клок общий).
2. "Доставляет" события из `replay_feed_<track>.parquet` (заранее подготовлены
   `scripts/build_replay_feed.py` — только с 2025-07-01, честно "невиданный" моделью
   test-период) в оперативную таблицу `channel_events`, скользящее окно 7 суток (раздел 7.2
   плана).
3. Для каждого трека считает признаки (те же, что при обучении — `scripts/build_features*.py`)
   напрямую SQL-запросами к `channel_events`, прогоняет через свой `catboost_<track>.cbm`.
4. При вероятности ≥ рабочего порога трека (лучшая точка эпизодной оценки, не целевой
   0.7/0.5 — см. `TRACKS` и `docs/analysis/model_report_<track>.md`, раздел 3) — находит
   открытый риск-кейс по каналу или создаёт новый с категорией трека, пишет `Prediction`.

## Честные ограничения

- Рабочие пороги (0.55 / 0.53) не удовлетворяют целевым Precision>0.7/Recall>0.5 — см.
  `docs/analysis/model_report_*.md`. Тема 3 CSV с ответами организаторов подтверждает: это
  плановые, не жёсткие требования, снижение порога допустимо при обосновании.
- Источник — заранее подготовленные файлы, а не реальный адаптер СМВУ (тот остаётся внешней
  зависимостью, см. `План_реализации.md`, раздел 4 «Что не входит»).
- Риск-кейсы не закрываются автоматически — только вручную через `/risk-cases/{id}/decisions`.
- Нет ретраев/dead-letter при сбое — при падении worker просто перезапускается
  (`restart: unless-stopped`) и продолжает с последнего сохранённого `virtual_time`.

## Локальный запуск

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-worker.txt
export JKH_DATABASE_URL=postgresql+psycopg://jkh:jkh@localhost:5433/jkh
export REPLAY_DATA_DIR=../data  # содержит replay_feed_<track>.parquet и catboost_<track>.cbm для обоих треков
python3 -m app.workers.replay_worker
```

Скорость воспроизведения — `REPLAY_SLEEP_SECONDS` (по умолчанию 2 секунды реального времени
на 1 час виртуального; полный test-период ~1 год займёт часы непрерывной работы — это
ожидаемо для развёрнутого сервиса, а не для однократного просмотра).
